## 摘要

搭建一个自用 API 中转站，用服务器端保存 OpenRouter API Key，对外提供受控的
OpenAI 兼容接口。客户端只访问自己的中转站，不直接接触 OpenRouter 密钥。
本阶段只列开发文档，不编写业务代码。

## 目标

实现一个最小可用、可扩展、可部署的中转服务：

- 对外提供 OpenAI 兼容的 `/v1/chat/completions` 接口。
- 服务端将请求转发到 OpenRouter 的 `https://openrouter.ai/api/v1/chat/completions`。
- 支持普通响应和流式响应。
- OpenRouter API Key 只保存在服务端环境变量中，不写入代码、文档或日志。
- 对访问中转站的客户端增加一层自己的鉴权，避免中转站被公开滥用。
- 保留后续扩展到模型列表、使用量统计、限流、管理面板的空间。

## 非目标

- 本阶段不写代码。
- 第一版不做复杂管理后台。
- 第一版不做用户注册、充值、计费系统。
- 第一版不代理所有 OpenRouter 端点，只优先代理 chat completions。
- 第一版不把 OpenRouter 密钥提交到仓库，也不在文档中记录真实密钥。

## 背景

- 用户已经注册 OpenRouter 并创建过一个 API Key。
- 该 key 已经出现在聊天中，应按“已暴露密钥”处理。
- OpenRouter 官方文档说明，请求使用 Bearer Token 认证。
- OpenRouter 官方文档说明，使用 OpenAI SDK 时可将 base URL 指向
  `https://openrouter.ai/api/v1`。

- OpenRouter 建议 API Key 使用环境变量保存，并在怀疑泄露时删除旧 key、创建新 key。

## 约束

- 真实 OpenRouter API Key 不得写入仓库。
- 真实 OpenRouter API Key 不得出现在日志、错误信息、测试快照或示例文件中。
- 因当前 key 已暴露，正式开发前必须重新生成 key，并废弃旧 key。
- 对外接口必须有自己的鉴权层，不能把中转站无保护地暴露到公网。
- 默认只允许白名单模型，避免客户端随意调用高价模型。
- 默认开启请求体大小限制，避免异常大请求拖垮服务。
- 日志默认只记录必要元数据，不记录用户完整输入和模型完整输出。
- 流式响应必须尽量原样透传，不能破坏 OpenAI 兼容客户端的读取方式。
- 错误返回需要保留足够信息用于排查，但不能泄露服务端密钥或内部路径。

## 建议架构

客户端请求流程：

1. 客户端把请求发到自己的中转站。
2. 中转站校验客户端 token。
3. 中转站检查模型白名单、请求大小和基础参数。
4. 中转站从环境变量读取 OpenRouter API Key。
5. 中转站把请求转发到 OpenRouter。
6. 中转站把响应或流式数据返回给客户端。
7. 中转站记录必要的请求元数据和错误信息。

建议的第一版接口：

- `GET /health`：健康检查。
- `GET /v1/models`：OpenAI 兼容模型列表，返回本地白名单模型。
- `POST /v1/chat/completions`：OpenAI 兼容聊天接口。
- `POST /v1/messages`：Anthropic/Claude 兼容消息接口。
- `GET /models`、`POST /chat/completions`：兼容把 Base URL 填成根地址的客户端。

建议的环境变量：

- `OPENROUTER_API_KEY`：OpenRouter 服务端密钥。
- `RELAY_API_KEY`：访问自己中转站的客户端密钥。
- `OPENROUTER_SITE_URL`：可选，用于 OpenRouter app attribution。
- `OPENROUTER_APP_TITLE`：可选，用于 OpenRouter app attribution。
- `ALLOWED_MODELS`：可选，逗号分隔的模型白名单。
- `PORT`：服务监听端口。

## 风险与回滚

- 风险：OpenRouter API Key 泄露，导致额度被滥用。
  - 回滚：立即删除旧 key，创建新 key，并检查访问日志。

- 风险：中转站无鉴权暴露到公网。
  - 回滚：停止服务或关闭公网入口，补上鉴权后再开放。

- 风险：模型无限制调用导致费用不可控。
  - 回滚：启用模型白名单、额度限制和 OpenRouter 侧 credit limit。

- 风险：日志记录了敏感 prompt、completion 或密钥。
  - 回滚：删除敏感日志，修正日志策略，重新部署。

- 风险：流式响应处理不正确，导致客户端卡住或解析失败。
  - 回滚：先关闭流式代理，仅保留非流式接口，修复后再开启。

## 决策记录

- 2026-05-20：第一版定位为自用中转站，而不是完整商业 API 平台。理由是先降低范围，优先完成安全可用的代理能力。
- 2026-05-20：第一版优先实现 `/v1/chat/completions`。理由是它是最核心的 OpenAI 兼容聊天入口。
- 2026-05-20：必须增加自己的中转站鉴权。理由是 OpenRouter Key 在服务端集中保存，如果中转站公网裸露，会变成可被滥用的免费入口。
- 2026-05-20：真实密钥只允许通过环境变量注入。理由是降低泄露、提交到仓库和日志外泄风险。
- 2026-05-20：本地第一版使用 Node.js 内置 HTTP 和 fetch 实现，不引入第三方依赖。理由是当前 npm 在 PowerShell 执行策略下不可直接运行，且无依赖服务更容易本地启动。
- 2026-05-20：模型列表由本地 `ALLOWED_MODELS` 生成，而不是直接透传 OpenRouter 全量列表。理由是客户端只应看到当前中转站允许调用的模型。
- 2026-05-20：`/v1/messages` 采用直接透传到 OpenRouter Anthropic Messages API，不在本地转换消息结构。理由是减少协议转换错误，并保持 Claude 兼容客户端的原始请求格式。
- 2026-05-20：404 响应回显收到的路径，并在终端打印 `relay_route_not_found`。理由是不同客户端测试模型的探测路径不完全一致，需要快速定位真实请求路径。
- 2026-05-20：根路径 `/` 改为本地聊天 UI，机器可读状态移动到 `/status`。理由是用户直接打开根地址时应进入可用界面。
- 2026-05-20：前端使用 Fetch ReadableStream 读取 SSE，不引入外部前端依赖。理由是后端已支持流式透传，前端本地解析即可满足可视化体验。
- 2026-05-20：会话历史先保存在浏览器 localStorage。理由是本地自用阶段不引入数据库，也不把对话写入服务端日志。
- 2026-05-20：模型池分为“免费池”“编码优先”“全部可用”，备用池来自 `FALLBACK_MODELS`。理由是用户希望有一个自动挑免费模型的池子，而不是手工固定一个模型。
- 2026-05-20：任务路由根据输入内容选择模型。理由是代码问题优先 coder，普通中文问题优先免费池，减少手动切模型成本。
- 2026-05-20：流式请求增加 idle 超时提示。理由是上游断流或卡住时，前端必须给出明确反馈。
- 2026-05-20：本轮优先做前端工作台体验，不改后端代理协议。理由是当前主要痛点是 UI 简陋和日常使用不顺手。
- 2026-05-20：会话高级操作继续保存在浏览器 localStorage。理由是本地自用阶段不引入数据库，降低部署复杂度。
- 2026-05-20：重新生成和继续生成复用同一套发送流程。理由是减少普通发送、重试和续写之间的状态差异，降低后续维护成本。
- 2026-05-20：前端发送本轮 prompt 时跳过当前用户消息和占位助手消息，再把 prompt 追加到 messages。理由是避免当前问题在上下文里出现两次，影响模型判断。
- 2026-05-20：流式打字机效果优先使用本地原生渲染器，不引入 `typed.js` 等第三方插件。理由是聊天流式内容是持续追加的动态文本，原生队列更容易和 SSE、停止生成、Markdown 渲染配合，也保持当前零依赖部署方式。
- 2026-05-20：前端先拆出 Markdown 渲染、SSE 解析和打字机渲染三个模块。理由是这些能力边界清楚，能减少主入口文件体积，后续再继续拆会话、设置、请求逻辑。
- 2026-05-20：浏览器端无法对一次已经断开的 POST SSE 原连接做真正断点重连。理由是上游没有提供事件 id 和可恢复游标；本轮采用“检测异常断流后带上下文自动续写”的恢复方式。
- 2026-05-20：自动续写最多尝试有限次数，并把续写内容接到同一条助手消息里。理由是既减少长文本半截停止，又避免无限循环消耗额度。
- 2026-05-20：续写时根据上一段助手内容判断是否处在代码块内。理由是代码块中断时，模型如果重新输出说明文字或新的围栏，会破坏同一条消息里的代码连续性。
- 2026-05-21：本轮使用 Ant Design skill 作为 React UI 决策依据，并通过本地 `antd.cmd info ... --format json` 查询 Button、Input、Select、Layout、Card、Tag、Slider、Switch、Tooltip、Modal、ConfigProvider 组件 API。理由是避免凭记忆使用未确认的组件参数。
- 2026-05-21：React 前端采用 Vite 构建到现有 `public/`，后端静态服务保持不变。理由是用户仍可用 `node src/server.js` 启动同一个本地中转站，同时前端源码可以按组件拆分维护。
- 2026-05-21：视觉方向采用 Linear / Vercel 式低饱和工作台：黑白灰为主、细边框、弱阴影、紧凑层级、减少装饰性渐变。理由是当前项目是高频使用的本地 AI 控制台，应该优先清晰、稳定、专业，而不是视觉噪音。
- 2026-05-21：logo 使用代码内联 SVG，而不是生成位图。理由是应用侧栏标识需要小尺寸清晰、可随主题缩放、构建轻量，SVG 比图片更适合。

- 2026-05-21：本轮先用轻量 SVG 趋势图，不额外引入 ECharts。理由是当前只需要小型趋势和健康概览，避免为右栏小图增加较大的图表依赖；后续需要完整仪表盘时再接 ECharts。

## 本轮升级范围：工作台化 UI 与使用体验

目标：

- 让页面更像一个长期可用的 AI 工作台，而不是临时测试页。
- 提升代码分析场景的可读性和操作效率。
- 补齐会话管理里的常用动作。

本轮要做：

- UI 视觉升级：更清晰的三栏工作台、模型标签、状态区、按钮层级。
- 会话管理：重命名、删除、置顶。
- 输入效率：添加常用 prompt 模板按钮，例如解释代码、找 bug、优化、总结。
- 消息体验：代码块增强，并支持代码块一键复制。
- 模型体验：显示当前选择模型的标签，发送后记录实际使用模型。

本轮不做：

- 不引入数据库。
- 不接入账号登录。
- 不做公网部署。
- 不改 OpenRouter 转发协议。

验收标准：

- 打开 `http://localhost:3000` 后页面仍可正常加载。
- 会话可重命名、删除、置顶。
- 模板按钮能把对应提示词插入输入框。
- 助手回复中的代码块有复制按钮。
- 页面能显示模型标签和消息使用的模型。
- 现有 `node --test` 通过。

## 本轮追加升级范围：生成恢复与输入反馈

目标：

## 本轮追加升级范围：控制台降噪与文件输入入口

目标：

- 去掉不必要的密钥和输入元信息展示，让页面更像正式控制台而不是调试页。
- 在输入区新增文件入口，先支持文本、代码、Markdown、JSON 等可直接读入 prompt 的文件。
- 继续丰富侧边栏和右侧控制台的“可填充区域”，让每个面板都有明确用途和信息密度。
- 增加轻量动画，让流式、消息、标签和输入区的状态变化更顺滑。

背景：

- 用户反馈设置页里的连接访问密钥不需要展示，输入框底部 `0 字 · openrouter/free` 没有实际价值。
- 用户希望后续支持上传文件，但 OpenRouter/OpenAI 兼容模型并不是全部支持图片、PDF、音频等多模态输入。
- 当前最稳妥的第一步是把文本类文件读取为上下文片段追加到输入框；图片和 PDF 后续按模型能力表单独接。

影响范围：

- `web/src/components/Composer.jsx`：移除输入元信息，新增上传按钮和文本文件读取入口。
- `web/src/components/ChatPanel.jsx`：把文件读取结果从输入区传给主应用。

- `web/src/App.jsx`：保留内部 relay key 状态，不再把它传给右侧设置 UI；新增文件内容注入 prompt 的处理。
- `web/src/styles.css`：补充上传区、附件提示、面板动画和控制台降噪样式。

约束：

- 不把真实 OpenRouter key 或 relay key 写入代码、文档、构建产物或可见 UI。
- 不在本轮改变后端转发协议，不新增数据库。
- 不假设所有模型都支持原生文件；文本文件先转成普通上下文发送。
- 文件大小需要有限制，避免一次把过大文件塞进 prompt 导致请求失败或成本不可控。
- Ant Design 组件改动前需要查询本地 `antd` API，改动后需要运行 `antd.cmd lint web --format json`。

验收标准：

- 设置页不再出现访问密钥输入框或密钥明文/掩码展示。
- 输入区底部不再出现 `0 字 · openrouter/free` 这类元信息。
- 输入区可以选择文本类文件，并把文件名和内容以清晰格式追加到 prompt。
- 上传非文本或过大文件时有明确提示，不会静默失败。
- 右侧控制台仍保持多标签结构，侧边栏和面板内容更像可持续扩展的工作台。
- `npm run build`、`node --test`、`antd.cmd lint web --format json` 通过。

验证方式：

- 手动检查设置页和输入区，确认不再展示访问密钥和输入元信息。
- 使用一个小型 `.txt` 或 `.js` 文件验证文件内容能追加到输入框。
- 使用超出限制或不支持的文件类型验证错误提示。
- 运行 `npm run build` 验证前端构建。
- 运行 `node --test` 验证后端兼容逻辑未被破坏。
- 运行 `antd.cmd lint web --format json` 验证 Ant Design 用法。

风险和回滚：

- 风险：用户误传过大文件导致 prompt 过长。
  - 回滚：保留上传入口但降低文件大小限制，或暂时禁用上传按钮。
- 风险：二进制文件被当成文本读取后出现乱码。
  - 回滚：收紧文件类型白名单，只允许明确文本扩展名。
- 风险：隐藏访问密钥后调试不方便。
